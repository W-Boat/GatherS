## 1. 重构目标与原则

**目标**：产出架构干净、可测试、可扩展、体验完整的 GatherS，而非"能跑"的堆叠代码。

**原则**
- 单向数据流：UI 只读状态、只发事件；状态只经 ViewModel 变更。
- 分层清晰：UI / 应用状态 / 领域用例 / 数据源 四层，依赖只向下。
- 接口驱动：识别、打标、AI、扫描器等核心能力以接口定义，默认本地实现，可替换。
- 本地优先：隐私不妥协，联网能力一律可关、可说明。
- Miuix 优先：界面组件以 Miuix 为准，不自绘、不重复造轮子。
- 可测性：领域层与数据层为纯 Kotlin，可脱离 Android 单元测试。

## 2. 新架构总览（方向）

- **UI 层**：Compose + Miuix 组件，按 feature 组织页面；统一导航图替代手动状态切换。
- **应用状态层**：ViewModel + StateFlow，页面状态收敛、可保存/恢复。
- **领域层**：截图实体、标签体系、智能规则、回收站、报表为独立领域模块（纯逻辑，无 Android 依赖）。
- **数据源层**：MediaStore 扫描器、索引存储、元数据提取，全部抽象为接口 + 可替换实现。
- **可插拔 AI**：识别/摘要/分类接口，本地启发式为默认实现，云端 AI 为可选注入。
- **导航**：明确的导航图（tab + 详情 + 弹层），转场动画统一处理。

**包结构取向**：`feature/*`（按功能分模块）+ `core/*`（领域/数据/通用）替代当前平铺的 data/ui 两层。

## 5. 技术选型补充（方向性建议）

- 状态管理：ViewModel + StateFlow（沿用现依赖，不引入重型框架）。
- 索引存储：轻量 JSON 索引 vs Room —— 重构时以"数据量级 + 可迁移性"权衡决定。
- 图片加载：内置采样解码 vs 引入成熟图片库 —— 以性能和稳定性为准。
- 依赖注入：极简手工注入即可，不引入框架（小工程）。
- 测试：领域层纯 Kotlin 单测先行。
